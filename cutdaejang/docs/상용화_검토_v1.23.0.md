# 컷대장 상용화 검토 (v1.23.0 기준, 2026-08-01)

> 회원님 지시: "일단 업데이트는 잠깐 멈추고 이제 상용화를 하기 위해서 검토를 하자 —
> 기능부터 디자인 사용방법 등 제대로 되어 있는지"

판매 대상은 컴퓨터 초보(카페 회원, "할아버지도") 100~1000명. 그 기준으로
**기능 완성도 · 안정성 · 화면/사용성 · 설치·문서 · 법적·비용 리스크** 5개 축을 전수 감사했다.
아래 항목은 전부 **코드 근거(file:line)** 또는 **실제 화면 실행 결과**가 있는 것만 적었다.
추측은 「실행 검증 필요」로 따로 표시했다.

**검토 방식**: 코드 감사 5건 병렬 + 실제 프로그램을 리눅스 컨테이너에서 띄워 화면 촬영·조작 실측
(깨끗한 새 PC 상태 사본으로 첫 실행 재현 포함). 전체 테스트 790개는 통과 상태.

## 0. 한 줄 결론

**기능·품질은 판매 가능한 수준에 도달했다. 그러나 지금 그대로 팔면 안 된다.**
막는 것은 기능이 아니라 ① 일반 zip의 **FFmpeg 자동설치가 100% 실패**하는 배치 버그,
② **판매용 문서(약관·환불·라이선스)가 하나도 없고 내부 문서가 통째로 고객에게 배포**되는 것,
③ 새 버전 알림 채널이 **빈 채로 출고**되어 고치더라도 전달할 길이 없는 것 — 이 세 가지다.
셋 다 코드 난이도는 낮고, 하루~이틀이면 해결된다.

## 2. 🔴 판매 차단 — 반드시 고칠 것

### 2-1. FFmpeg 자동 다운로드가 구조적으로 100% 실패 (최우선)

`1_설치.bat`의 `else (...)` 블록 **안에서** `set "FFURL=..."`(39행)을 하고
같은 블록 안에서 `%FFURL%`(41행 curl, 44행 PowerShell)을 쓴다. cmd는 괄호 블록을
**통째로 파싱하면서 `%VAR%`를 먼저 치환**하므로, `set`이 실행되기 전에 확장되어 값이 빈다.
`setlocal enabledelayedexpansion`도 없다(3행).

- 결과: 다운로드가 시작조차 안 되고 `[!] 다운로드 실패 — 인터넷 연결을 확인하세요`(47행).
  인터넷은 멀쩡한데 인터넷 탓을 하니 **고객이 자가 해결할 수 없다.**
- `2_UI실행.bat:27`이 FFmpeg 없을 때 이 경로를 자동 호출하므로 **UI 실행도 같이 막힌다.**
- **26번(설치가 안 됨) 항목의 진짜 원인이 이것일 가능성이 높다.** 당시 "파이썬 설치 장벽"으로
  진단하고 「설치포함」 zip으로 우회했는데, 그 우회 덕분에 이 버그가 가려져 있었다.
- 전 bat 전수 스캔 결과 **이 한 곳만** 해당(나머지 6개 파일은 정상).

**고치는 법(택1)**: (a) 3행을 `setlocal enabledelayedexpansion`으로 바꾸고 41·44행을 `!FFURL!`로,
(b) URL을 41·44행에 직접 인라인(블록 안 변수를 아예 없앰 — 가장 안전),
(c) `set FFURL`을 블록 바깥(33행 위)으로 이동.
→ **반드시 실제 윈도우 PC에서 `windows\ffmpeg` 폴더를 지우고 1회 재현 테스트.**

`배포_가이드.md`(1행에 **"사장님 전용"**이라 적혀 있음) · `편집기_로드맵_v2.md` ·
`로드맵_남은작업.md` · `개발기획안_v1.2.md` · `POC_REPORT.md` · `PATCH_v0.3_보고서.md` ·
`수정내역_v1.09.0/v1.10.0/v1.10.1.md` · `카페가이드.txt`(이것만 고객용)

- 고객은 "아직 안 되는 기능"과 "알려진 오류" 목록을 먼저 읽게 된다 → 불신·환불 요구.
- 경쟁사 대응 전략과 배포 운영법이 그대로 넘어간다.
- `업데이트.bat:88`이 매 업데이트마다 `docs\` 전체를 고객 PC에 다시 덮어쓴다.
- 추가로 `실행가이드.md:31`에 **내부 GitHub 저장소 주소와 브랜치명**이 그대로 있다.

**고치는 법**: 배포용 `docs/`는 화이트리스트로 `카페가이드.txt` + 새로 만들 판매 문서만.
`업데이트.bat`의 복사 대상도 같은 화이트리스트로 좁힌다. `실행가이드.md`의 개발자 섹션 삭제.

### 2-3. 판매에 필요한 문서가 zip 안에 하나도 없음

전수 확인 결과 `LICENSE`/`이용약관`/`환불`/`지원안내`/`개인정보` 파일이 **0건**
(있는 것은 폰트용 `resources/fonts/OFL-LICENSE.txt` 하나뿐).
화면에도 문의 창구가 없다 — `🩺 진단 리포트 (문의할 때 복사)` 버튼은 있는데
**어디로** 문의하는지가 없다.

- 고객은 "무엇을 산 것인지"(사용 범위·PC 대수·재판매 가능 여부), "안 되면 어떻게 하는지"(환불),
  "누구에게 말하는지"(카페 게시판)를 알 수 없다.
- 한국 전자상거래법상 유료 소프트웨어는 청약철회 조건 고지가 사실상 의무이고, 분쟁 시 판매자가 불리하다.
- **라이선스 키가 없다는 점**(23번 3단계 미구현)은 지금 당장은 약관 문구로만 대응 가능하다:
  재배포 통제 불가 · 환불자 사용권 회수 불가 · 구매자 식별 불가.
  1000명 규모에서는 완전한 DRM보다 ①구매자 이름을 박은 `라이선스.txt` 동봉(워터마킹) →
  ②키 입력 명목형 → ③서버 검증 순의 단계 도입이 현실적이다.

**판매 전 새로 넣을 문서 (7종)** — 상세는 §6 체크리스트.

### 2-4. 새 버전 알림이 꺼진 채로 출고

`cutdaejang/update_url.txt`에 주석만 있고 **활성 주소가 0줄**이다.
소비처는 `config.py:134` → `webui.py:2856`, 비어 있으면 "배포 주소가 설정되지 않았어요"만 반환하고
하루 1회 자동 확인도 아무 일도 하지 않는다.

- v1.18에서 만든 "새 버전 자동 알림"이 **작동하지 않는 상태로 나간다.**
- 1000명이 각자 다른 버전에 고정되고, 2-1 같은 치명 버그를 고쳐도 **전달할 통로가 없다.**

**고치는 법**: 첫 판매 zip을 만들기 전에 `update_url.txt`에 version.json 주소 기입 —
릴리스 체크리스트 1번. 값이 비면 빌드가 실패하도록 강제하는 것이 확실하다.

### 2-5. 「랜덤」 BGM을 쓰면 CC BY 크레딧이 생성되지 않음

- `orchestrator.py:216-220` `resolve_bgm("random")`은 실제 Kevin MacLeod 곡을 무작위로 골라 **사용한다.**
- `webui.py:1621` `_bgm_credit()`은 `bgm_name == "random"`이면 **빈 문자열을 반환**한다.
- 「랜덤」은 UI에 실제로 노출된다(`webui.py:9766`, `11201`, `11202` — 생성·편집 폼 모두).

CC BY의 유일한 조건이 저작자표시인데, 랜덤을 고른 고객은 곡을 쓰고도 크레딧을 한 줄도 못 받는다.
**판매되는 도구가 고객의 저작권 위반을 구조적으로 유발한다.**

**고치는 법**: `resolve_bgm`이 실제 선택된 파일명을 작업에 되돌려 기록하고 `_bgm_credit`이 그 값을 쓰게.
(임시 대응으로는 랜덤 선택 시 완료 화면에 "실제 사용곡: ○○○" 노출)

### 2-6. 인터넷이 끊기면 목소리 폴백 체인이 전부 무력화

설계상 `gemini → openai → 윈도우 내장음성 → stub` 폴백이 준비돼 있는데,
DNS 실패·연결 거부(`URLError`)와 읽기 타임아웃(`TimeoutError`)이 **어느 except에도 안 걸려**
단 한 단계도 작동하지 않고 작업이 즉사한다. 화면에는 영문 원문만 뜬다.

- `tts_engine.py:69-85` `_http_post_json`이 `HTTPError`만 처리
- `tts_engine.py:971-1008`, `:1295` 폴백 루프의 except가 `URLError`를 포함하지 않음
- 감사 과정에서 **실제로 재현 확인됨**(URLError 발생 시 windows/stub까지 전부 건너뜀)
- 악화 요인: 타임아웃이 120초/300초/600초로 길다 → 카페 와이파이 같은 환경에서
  **10분간 진행률 0%로 무반응** 후 영문 오류

같은 결함이 `script_generator.py`(대본·훅·썸네일 13곳), `stt_engine.py`, `video_gen.py`에도 있다.
(`background_generator.py:146-148`만 `except Exception`이라 유일하게 안전)

**고치는 법**: `_http_post_json`과 각 provider의 `urlopen`에서 `URLError`/`TimeoutError`를
재시도 가능한 오류로 변환하고, 폴백 루프의 except를 넓힌다. 타임아웃도 30~60초로 낮춘다.

### 2-7. ✨AI 클립이 항상 가로(16:9)로만 생성된다

구간 카드에서 「📱 세로 쇼츠(9:16)」를 골라도 AI 클립 요청은 비율이 하드코딩돼 있다
(`webui.py:8834` `aspect: '16:9'` — `secLayout` 라디오를 보지 않음).

- 세로 쇼츠 구간에서 [✨ AI 클립]에 **약 1,050원(Veo 5초)을 결제**했는데, 받은 클립이 가로라
  최종 영상에서 위아래가 블러 띠로 채워지고 실제 화면은 3분의 1만 차지한다. 잘리진 않지만 못 쓴다.
- 게다가 캐시 키(`video_gen.py:96-99`)에 `aspect`가 빠져 있어, **비율을 고쳐도 같은 프롬프트면
  옛 가로 클립이 그대로 재사용된다.** 둘을 같이 고쳐야 한다.

**고치는 법**: `aiClipGo()`에서 `pick('secLayout')==='shorts' ? '9:16' : '16:9'`를 전달하고,
`clip_cache_path()` 키에 `aspect` 추가. (합쳐서 2~3줄)

## 5. 잘 되어 있는 것 (건드리지 말 것)

실측·코드로 확인한 강점이다. 상용 제품으로서 이미 경쟁력이 있는 부분.

1. **키가 하나도 없는 첫 실행** — 실제로 새 PC 상태를 재현해 확인했다. 첫 화면에
   "💡 처음 오셨나요? — 준비물 1개 (1분)" 배너 + 무료 발급 링크가 뜨고, [생성 시작]을 누르면
   키 입력 프롬프트 → "키 없이 계속할까요?" 확인 → 취소하면 이유까지 배너로 설명한다.
   **키 0개로도 영상이 완성되고**(내장 음성·그라데이션 배경), 각 단계에서 왜 대체됐는지 한국어로 알려준다.
2. **쉬운 모드** — 화면 글자 수가 1311→594자. ①주제 ②목소리 ③꾸미기(접힘) + 큰 [생성 시작].
   "할아버지도" 목표에 정확히 부합한다. **이걸 기본값으로 삼는 것을 권한다.**
3. **AI 영상 만들기 화면** — 단계 번호·큰 시작 버튼·접힌 옵션 6개. 그대로 팔아도 되는 완성도.
4. **AI 클립 과금 안전장치** — 예상 금액 원화 표시 + `confirm()` + 월 한도 기본 1만원 + 캐시 재사용 무과금 +
   "예상치" 정직 표기. 돈 나가는 기능 처리의 정석(단, §3의 단가 0 예외만 수정).
5. **설정 화면 2단 구성** — `👵 자주 바꾸는 것`을 펼쳐 두고 나머지 33개를
   `🔧 전문가 설정 — 몰라도 됩니다` 아래 그룹으로 접었다.
6. **완성 후 안내** — 미리보기 + 파일 경로 + 5개 플랫폼 업로드 키트 + `🎯 다음엔 이것도 해보세요`.
7. **봇 차단 우회 코드 없음** — captcha 라이브러리·자동 로그인·UA 위장·webdriver 패치 **전부 0건**.
   헤드리스가 자신을 HeadlessChrome으로 정직하게 알리고, CDP는 읽기 전용 최소 동작만 한다.
8. **보안 기본기** — 서버는 127.0.0.1 전용 바인딩, POST에 Host+Origin CSRF 방어,
   API 키는 전부 헤더 전송(URL 노출 없음), 예외 메시지에 키가 안 실림, 파일 서빙은 화이트리스트/토큰.
   **api_keys.json은 .gitignore로 차단돼 git 히스토리에 올라간 적이 없다**(확인 완료).
9. **손상 복구력** — settings.json이 깨져도 기본값으로 실행 후 자가 치유, api_keys·history.db 손상도 방어.
   브라우저 새로고침(F5)해도 진행 중 작업이 사라지지 않는다.
10. **렌더 자가검증** — 길이·오디오·해상도를 ffprobe로 검증하고 실패 시 CPU로 재시도, GPU 실패도 폴백.
11. **TTS 429 처리** — 분당/일일 한도 구분 + 슬라이딩 윈도우 + 카운트다운 표시.
    **이 수준을 대본 생성 등 다른 API 경로에도 확산시키면 된다.**
12. **폰트 라이선스** — Pretendard + OFL 전문 동봉으로 재배포 조건 충족.
13. **배선이 11,576줄 규모에서 불일치 0건** — 이게 가장 놀라운 결과다. 전수 대조 확인:
    - **죽은 버튼 0건** — 화면에서 부르는 함수 156종이 전부 정의돼 있음
    - **없는 id 접근 0건, 중복 id 0건** — 접근하는 363종이 전부 실재
    - **끊긴 API 0건** — 서버 라우트 65개 ↔ 화면 호출 65개 **완전 일치**(없는 걸 부르는 것도, 만들어만 두고 안 쓰는 것도 없음)
    - **설정 반영 누락 0건** — 기본값 84개 키가 전부 실제로 읽히고, ⚙설정 입력 36개 = 저장 36개 = 복원 36개
    - **라이브 스모크 테스트** — 서버를 띄워 POST 44개에 빈 요청을 넣었더니 **500·미처리 예외 0건**,
      전부 한국어 안내가 담긴 400/404로 응답
    - **미완성 흔적 0건** — TODO/FIXME/NotImplemented 없음. "준비 중" 문구 3곳은
      v1.23.0에서 넣은 정직한 고지(대안까지 안내)이지 죽은 기능이 아님

## 8. 실행 검증이 필요한 항목 (리눅스 컨테이너에서는 확정 불가)
