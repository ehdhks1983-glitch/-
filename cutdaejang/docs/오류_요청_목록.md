  긴 대본(구간당 5~10줄)을 확인하기 어렵다

  - 스크롤 없이 전체 구간 대본을 한 번에 훑는 보기도 검토

### 9. 구간마다 [화면] 메모 · 나레이션 · [자막] 을 따로 넣기 — 미착수 · [최우선]
- 배경: 회원님 촬영 대본은 구간마다 성격이 다른 3가지가 섞여 있다
  ```
  ① 오프닝 — 0:00 ~ 0:15
  [화면] 프로그램 실행 직후 전체 화면. 왼쪽 사이드바를 마우스로 천천히 훑기.
  나레이션 안녕하세요. 티스토리 블로그 AI 퍼블리셔입니다. …
  [자막] 키워드 입력 → AI 글 작성 → 이미지 생성 → 자동 발행
  ```
- 현재 문제: 구간 한 칸에 **내레이션 입력란 하나뿐**(`sec-narr`, 9602~9606행).
  그래서 위 대본을 붙여넣으면 `[화면] …`, `[자막] …` 줄까지 **AI가 그대로 낭독**하고,
  `[자막]`은 화면에 자막으로 박히지도 않는다
- 요청 기능 — 구간 행을 3칸으로
  | 칸 | 성격 | 동작 |
  |---|---|---|
  | 🎬 화면 | 뭘 찍을지 **나만 보는 메모** | 낭독 ✕ · 화면 표시 ✕ (촬영 참고용) |
  | 🎙 나레이션 | 소리로 읽을 말 | TTS 낭독 + 기본 하단 자막 |
  | 💬 화면 자막 | 화면에 크게 박을 **강조 한 줄** | 낭독 ✕ · **화면에 자막 카드로 번인** |
- 구현 메모: 💬 화면 자막은 **v1.07 텍스트 카드(ASS 오버레이)** 를 그대로 쓰면 됨
  (`core/text_cards.py` + `render_engine/ass_writer.py` `_card_lines`) —
  새로 만들 필요 없이 "이 구간 시작에 카드 1장" 으로 배치
- 대본 통째 붙여넣기도 같이 개선
  - `[화면]` / `나레이션` / `[자막]` 표기를 **자동으로 3칸에 나눠 담기**
  - `① 오프닝`, `2-1. 라이선스 인증` 같은 소제목 → **구간 제목**으로
  - `0:00 ~ 0:15` 시간 표기가 있으면 → **구간 범위**로 자동 반영

### 10. 구간에 영상을 끌어다 놓기(드래그 앤 드롭) — 미착수 · [높음]
- 요청: 구간마다 영상을 넣을 때 경로를 입력하거나 [클립 선택]을 누르지 않고
  **탐색기에서 파일을 끌어다 그 구간 칸에 놓으면** 바로 들어가게
- 현재: 구간 행의 영상 칸(`.sec-video`)은 경로 직접 입력 또는 [🎬 클립 선택] 픽커뿐
- 적용 범위: 구간뿐 아니라 **영상·사진을 넣는 칸 전부** 같은 방식으로
  (✂ 내 영상 편집의 영상 칸, 🖼 사진 칸, 🎤 녹음 파일 칸 등 — 한 곳만 넣지 않기)
- 구현 메모 (기술 제약 포함)
  - 브라우저는 보안상 끌어온 파일의 **PC 전체 경로를 그냥 알려주지 않는다**
    (`File` 객체에는 이름·크기만 있음). 그런데 컷대장은 경로가 필요하다
  - ① 1순위 시도: 윈도우 탐색기에서 끌어오면 `dataTransfer`의
    `text/uri-list`(또는 `text/plain`)에 `file:///C:/...` 전체 경로가 실려 오는
    경우가 많다 → 이걸 풀어서 경로 칸에 그대로 채우면 **복사 없이 즉시** 해결
  - ② 경로가 안 실려 오면: 파일을 서버(로컬)로 업로드해 작업 폴더에 저장 후 그 경로 사용
    — 다만 8분급 영상은 수백 MB라 복사 시간·디스크를 먹으므로 안내 문구 필요
  - ③ 그래도 안 되면: 기존 [클립 선택] 픽커를 자동으로 열어주는 폴백
  - 끌어오는 동안 칸에 **테두리 강조**(여기에 놓으세요) 표시

### 11. 단축링크(naver.me)가 쇼핑 링크로 인식 안 됨 — **원인확정** · [최우선]
> 1·2번(사진 0장)의 **이번 사례 원인이 이걸로 확정**. 다른 원인과 별개로 먼저 고칠 것.
- 재현: 🛒 쇼핑 발행 → 상품 링크에 `https://naver.me/FQu2awsL` → 사진 0장
- 원인(확정): `tools/product_page.py` 28~29행

  ```python
                 "shopping.naver.com", "11st.co.kr", "gmarket.co.kr", "auction.co.kr")
  ```
  **`naver.me`가 목록에 없음** → `is_shop_url()`이 거짓 →
  `gui/webui.py` 1834행·1888행의 **상품 사진 수집 분기를 아예 안 탐**
- 정황 증거
  - 진단 리포트(2026-07-28 19:23) 로그 200줄에 **쇼핑 수집 기록이 한 줄도 없음**
    (수집기가 돌다 실패한 게 아니라 **처음부터 안 돌았다**)
  - 같은 프로그램 `tools/fetch_web.py` 28~29행 `_PARTNER_HOSTS`에는
    **`naver.me`가 들어 있음** → 블로그 수집만 단축링크를 알아보고 상품 수집은 누락
- 예정 수정
  - `_SHOP_HOSTS`에 단축·파트너 도메인 추가: `naver.me`, `link.coupang.com`,
    `me2.do`, `m.coupang.com`(coupang.com로 이미 커버) 등
  - **리다이렉트 최종 주소로 한 번 더 판정** — 단축링크는 열어봐야 정체를 알 수 있으므로
    `is_shop_url(원본)`이 거짓이어도 한 번 따라가 최종 host로 재판정
  - `fetch_web._PARTNER_HOSTS`와 `product_page._SHOP_HOSTS`를 **한 곳에서 관리**해
    같은 종류의 누락이 다시 생기지 않게
- 참고(2차 원인 후보): 네이버 스마트스토어 사진은 확장자 없는 주소가 많은데
  `_IMG_RE`(31~40행)는 `.jpg/.png` 확장자로 끝나는 주소만 훑음 → 별도 확인 필요

### 12. [💾 임시 저장] 버튼을 모든 카드에 — 미착수 · [높음]
- 요청: 임시 저장 버튼이 **카테고리(카드)마다 다 있어야** 한다
- 현재 상태
  - **눈에 보이는 [💾 임시 저장] 버튼은 「🎞 구간 대본 영상」 카드 하나뿐**
    (`webui.py` 5625행, `/api/sec_draft`)
  - 나머지 카드(AI 영상·내 영상 편집·블로그 링크·쇼핑)는 **자동 저장만** 됨
    (`DRAFT_FIELDS` 8402~8407행, 입력 0.9초 뒤 조용히 `/api/draft` 저장)
    → 저장되고 있다는 **표시가 없어 회원님이 저장 여부를 확신할 수 없음**
  - 「🖼 사진 영상」은 전용 항목이 없고 편집 카드의 `photoPath` 하나만 딸려 있음
- 예정 수정
  - 모든 카드 하단에 **[💾 임시 저장] · [🗑 지우기]** 버튼을 같은 모양·같은 자리에
  - 누르면 **"저장했어요 ✓"** 를 잠깐 표시 (지금 구간 카드 방식과 동일하게)
  - 자동 저장은 그대로 두되, **마지막 저장 시각**을 작게 표시 ("2분 전 자동 저장됨")
  - 저장 대상 필드를 카드별로 재점검 — 지금 `DRAFT_FIELDS`는 핵심 몇 개만 담고 있어
    꾸미기·목소리·화질 같은 설정은 안 들어감 (구간 카드는 설정까지 저장 중)
  - 「🖼 사진 영상」 카드도 독립 항목으로 추가

### 13. 구간 영상 렌더가 갑자기 오래 걸림 (3분 영상 45분·98% 정지) — 조사중 · [최우선]
- 증상(2026-07-28): 3분짜리를 구간으로 나눠 각각 클립 넣고 제작 → **45분째 98%**
  화면 문구: `합본 위에 내레이션과 자막을 같은 시간표로 입히는 중…`
- **회원님 증언: 예전에 같은 3분·초고화질(4K)은 이렇게 오래 안 걸렸다** → 회귀로 판단
- 확인된 사실
  - 진행률 **98%는 고정값**(`webui.py` 1849행 `frac=0.98`) — 실제 진행률이 아니라
    "마지막 단계 진입" 표시. 그래서 몇십 분이든 98%에 멈춰 보임
  - 화면 문구 `합본 위에 … 입히는 중`은 **v1.11.0 zip 코드에 존재하지 않음**
    → 회원님은 **v1.11.0보다 새 빌드**를 사용 중 (그 빌드 코드 미확보)
- 원인 가설 (구조 변경에 따른 회귀)
  - 예전(v1.11.0 확인): 구간마다 자막을 구워 렌더 → 이어붙이기 → BGM은 `mix_bgm`으로
    **영상 재인코딩 없이 소리만** 섞음
  - 지금(새 빌드): 구간은 자막 없이 렌더 → 이어붙이기 →
    **합본 전체에 자막·내레이션을 다시 입힘 = 4K 전체 재인코딩 한 단계 추가**
  - 자막 굽기(libass)는 CPU 작업이라 GPU(nvenc)가 대신 못 하는 구간이 있음
  - 회원님 자막 설정이 **등장 효과 "타이핑"(`anim: "type"`)** → 4K에서 부담 가중
- ⚠ **화질을 낮추는 건 해법이 아님** — 회원님은 유튜브 노출 때문에 4K로 올린다.
  고칠 대상은 화질이 아니라 **마지막에 통째로 다시 굽는 구조**
- 다음 단계
  1. **지금 쓰는 빌드의 zip 확보** (필수 — 그 코드 없이는 확정 불가)
  2. 자막 효과를 기본(페이드)으로 바꿔 1회 측정 → 자막 굽기 부담인지 인코딩인지 분리
  3. 최종 단계 재인코딩 제거(구간별 자막 유지) 또는 GPU 활용 범위 확대
